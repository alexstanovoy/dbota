# dbota asset manifest: every Valve asset the client uses, converted by `dbota import` (and the
# browser's import) into the cache ($DBOTA_ASSETS, default ~/.cache/dbota/v<N>, N being the
# version in assets-manifest/version). Outputs are relative to the cache root.
#
# Line kinds (whitespace-separated, '#' starts a comment):
#   model   <logical> <vpk .vmdl_c> <out .glb> [anims=a,b,c] [meshes=m,n] [attach=<model>] [skin=<material group>] [model_scale=x]
#           glTF 2.0 binary; textures are PNG files next to the .glb (referenced by relative uri).
#           skin= draws it with that one of the model's skins (material groups: the sentry ward's "1").
#           anims= lists the exported animations (none without it); meshes= keeps only those
#           render meshes (drops event/alternate variants that would overlap the default one).
#           attach= marks a wearable: a skinned mesh whose joints share names with the parent's
#           skeleton; bind its joints to the parent's joint entities by name, ignoring case
#           (Dota "bonemerge"; e.g. the arms say root0_jnt where Shadow Fiend says Root0_JNT).
#   clip    <model> <logical clip> <glTF animation name> <duration s> [point=<s>]
#           point = the Dota attack/cast point in seconds at base speed (npc scripts), not a frame.
#   unit    <npc_units.txt unit name> <model logical>|none [model_scale=x] [attack=<particle logical>]
#           which model a unit is drawn with and the unit's own ModelScale (units may share a model at
#           different sizes). `none` draws nothing. attack= names the particle its attack's missile wears
#           (the unit's ProjectileModel). The importer skips these lines.
#   portraits <logical> <vpk scripts/npc/portraits.txt> <out .txt>
#           Dota's portrait framings (camera, field of view, light, background) of every model above, one
#           line each (model-local inches and degrees; the HUD portrait's camera is placed by them), and
#           each background's image under models/portrait_backgrounds/. Written by the Rust importer only;
#           a model Dota has no framing for is framed from its bounds, on a plain dark backdrop.
#   shop    <logical> <vpk scripts/shops.txt> <out .json> strings=<localization .txt>
#           the shop's categories and the items each lists, in Dota's order, and the shop's words
#           (category, tab and button names) out of the localization. Written by the Rust importer only.
#   texture <logical> <vpk .vtex_c> <out .png>
#   particle <logical> <vpk .vpcf_c> <out .json>
#           a particle system and every child under it, read into typed definitions, as one JSON file
#           (dbota_import's particle_json); their textures as KTX2 under textures/ beside it, with their
#           sprite sheets in the JSON. The client simulates and draws them (src/particles/).
#   sound   <logical> <vpk .vsnd_c> <out .wav|.mp3> event=<Dota sound event that plays it>
#           PCM WAV as Valve ships it (16-bit 44.1 kHz, a few 8-bit or 22.05 kHz); voice lines are MP3
#           in the game and stay MP3 (out .mp3). Events with several variants list one line per variant;
#           variants of one random pick (a hero's move acknowledgements) share the logical name.
#   fx      <subject>.<trigger> at=<where> [particle=<particle logical>] [sound=<sound logical prefix>] [cp1=<feed>]
#           an effect bound to a fact of the game by Dota's name for it (src/fx.rs). The importer skips these lines.
#           subject: item.<ids.txt item name> | modifier.<Dota modifier name> | unit.<npc_units.txt name>
#           trigger: use (the item was used) | land (the item thrown came down) | worn (the modifier is on a unit, or
#                    a unit of that name stands: from its start until it goes; the particle follows the unit)
#           at: caster (where the user stands after) | caster_before (where it stood before) | point (the spot the
#               use was aimed at, or the throw came down) | unit (the wearer; for worn only, and only for worn)
#           sound: one of the sounds whose logical name starts with it plays at that spot
#           cp1: what the particle's second control point is given: sight (how far the wearer gives true sight)
#   style   <vpk .vcss_c> <define>
#           a colour one of Dota's stylesheets defines (`@define name: #rrggbb[aa];`), written with
#           every other to text/styles.json under its name lower-cased, as #rrggbbaa.
#   label   <vpk localization .txt> <key>
#           one of Dota's interface texts (a stat's name, a line of the stats tooltip), written with
#           every other label to text/labels.json under its key lower-cased; the client fills its
#           {d:name} and {s:name} variables with the simulator's numbers.
#   world   <logical> <vpk .vwrld_c> <out .gltf> vpk=<map vpk under game/dota> half_width= v_min= v_max=
#           layers=<dir> trees=<file>: the default map cropped to a band around the mid-lane diagonal
#           (see tools/README.md for the coordinate convention, terrain layers and trees).
#           Models without anims= are static (buildings, fountains, trees, wearables).
#
# Coordinates: glTF Y-up metres; gltf.x = dota.y * 0.0254, gltf.y = height * 0.0254,
# gltf.z = dota.x * 0.0254; bota = dota + 9216 on both axes. Models face +Z (Dota +x at yaw 0).
